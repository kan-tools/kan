6. FINDINGS
F1 [LOW-MEDIUM, demonstrated] The private plan artifact is not protected from source SQLite sidecar
   names.
   - Code: kan-v2.rs:896 -> copy_upgrade.rs:139 retain_plan. It uses create_new with an fsync and a
     read-back, but performs no overlap check.
   - Compare backup/recovery: they use sqlite_destination (evidence_store.rs:418), which refuses
     "destination overlaps source SQLite files".
   - Probe A0 (raw/10-probes.txt):
     - `copy-plan SRC/archive.sqlite SRC/archive.sqlite-journal ...` exits 0 and reports a retained
       plan and pin.
     - copy-batch with that plan then fails with "attempt to write a readonly database". The
       read-only source reader sees a hot journal.
     - The next ordinary legacy Ledger::open(source) succeeds and DELETES the plan artifact
       (it treats it as a hot journal).
     - Source main bytes are unchanged.
     - Re-planning with the same nonce reproduces the same pin. Recovery is therefore possible only
       if the owner kept the nonce and the source is unchanged.
     - The -wal and -shm names were refused here only because the source reader had already created
       those files (EEXIST).
   - Effect: the CLI's "durably retains and verifies a private plan" guarantee (C1, design 705-714)
     can be silently voided by a path choice that the codebase's other outputs refuse. No evidence
     byte is altered.
   - Not tested: the effect on a LIVE legacy service that opens new connections while the file
     exists.
   - Follow-up: apply the sqlite_destination overlap/alias check for the source path (and refuse the
     destination root's archive.sqlite family) in retain_plan or the CLI, and add a regression test.
     Probe L shows that a plan at DEST/archive.sqlite is already refused safely ("File exists" /
     "file is not a database") with the plan bytes unchanged.

F2 [LOW, coverage] No committed test pins profile-3 unsupported-schema refusal.
   - The contract names it (Q6). The behavior is correct (probe C).
   - R2 (remove check_copy_schema from full_audit) survives the whole suite. That would silently
     weaken verify_file, CLI verify and backup-output verification. Archive::open keeps its own
     check.
   - Follow-up: commit probe C's four cases with the exact reason.

F3 [LOW, coverage/attribution] Resume prefix comparisons are unpinned.
   - Design 666-668 requires "before advancing, compare all existing original inventory/payload
     bytes against the source's exact prefix", and records likewise (copied.rs:403-429). R3 and R4
     survive.
   - incomplete_copy_backup_remains_incomplete_and_resume_checks_the_exact_prefix is actually caught
     earlier, by audit_state's payload-length check (copied.rs:185-195). Its name overclaims.
   - Admission stays safe because the completion digest never matches. Without the compares, though,
     a self-consistent foreign prefix would let resume sign fresh RV proofs into a copy that can
     never complete. The required early refusal is untested.
   - Follow-up: add a valid-but-foreign object/inventory row (correct hash and length, absent from
     the source) and assert the "differs from source prefix" reason.
   - R5 and R8 are structural guards unreachable through the API (INFO).

F4 [LOW, CLI coverage] The copy-batch `--copy-profile` requirement (kan-v2.rs:912) is not pinned
   (R9 survives).
   - Probe I0 shows it refuses correctly.
   - Committed CLI refusals cover only missing plan, wrong pin, (0,0) budget and changed source.
   - Follow-up: commit probe I's cases. They are cheap and attribute the user-facing preconditions

F5 [INFO] API Archive::create (copied.rs:239-251) creates output before any signer check.

9. VERDICT RATIONALE
**APPROVE WITH FOLLOW-UPS**

The profile-3 destination implements what the governing contract asks of this slice:
  - an externally pinned canonical recipe
  - immutable original membership, including staged objects
  - objects-first, budgeted, single-transaction batches that revalidate under the writer lock
  - retained-verified proofs only within the planned single-H prefix
  - admission gated on a completion that is recomputed from the exact source digest, both before
    and after staging
  - byte-preserving backup and rebuild that keep incomplete copies incomplete
  - explicit, non-inferred profile selection at every entry point I could find

I verified this by execution, not by reading the author's summary:
  - 136/136 tests, twice
  - 9/9 author controls with named failures
  - 3 of my mutants killed
  - 11 probe families (A-I, K, L) covering cross-profile entry points, the incomplete-admission matrix, H=C
    retries, CLI WAL source invariance, CLI incomplete lifecycle, preconditions and collisions

There is no invariant violation and no purpose laundering. Incomplete copies are not promoted.

The follow-ups are specific and do not undermine the north star:
  - F1: guard the plan artifact against source-sidecar names. This is a demonstrated custody loss
    with no evidence damage.
  - F2-F4: commit tests for behavior that is correct today but unpinned (schema drift, resume prefix
    comparisons, CLI flag/precondition refusals).
  - F5-F7: documentation and wording.
