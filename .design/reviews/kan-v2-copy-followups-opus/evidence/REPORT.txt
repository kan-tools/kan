5. FINDINGS
F-A [LOW-MEDIUM, demonstrated] The Unicode case-fold alias of the "-shm" suffix bypasses plan custody for both
    families. This is the residual of F1.
  - Filesystem: on this host's default case-insensitive APFS, "archive.sqlite-ſhm" (U+017F LONG S, which case-folds
    to 's') opens the same file as "archive.sqlite-shm". Shown by a scratch check and by P1's "alias visible as ASCII
    -shm: true".
  - Code: sqlite_destination (evidence_store.rs:418-455) compares names with eq_ignore_ascii_case, and the suffix
    alias check matches only ASCII suffixes.
    - The inode check covers the main file and existing bases, but not a sidecar name that does not exist yet.
    - The comment at :426 ("also protects case-insensitive volumes") overclaims.
    - The new design text ("same ... filesystem-alias collision rules") and AUTHOR's "including case/alias sidecars"
      overclaim to the same extent.
  - P1, destination family, real CLI (raw/10):
    - Setup: a legitimate first batch, after which the destination has no -shm. The plan bytes are placed at
      DEST/archive.sqlite-ſhm with mode 0600.
    - The ASCII -shm control is refused.
    - read_plan_for_copy(DEST/archive.sqlite-ſhm) returns Ok(379 bytes).
    - `copy-batch --resume --plan DEST/archive.sqlite-ſhm` exits 0 and writes a batch.
    - Afterwards the plan file is gone: SQLite used it as the WAL index and unlinked it on close. Source bytes are
      unchanged.
  - P3, source family (raw/11):
    - Setup: a legacy writer closes cleanly, after which the source has no sidecars. The plan is placed at
      SRC/archive.sqlite-ſhm.
    - read_plan_for_copy returns Ok, and PlannedCopy::confirm succeeds.
    - The plan bytes are rewritten while the source reader is open. The next legacy writer open/close deletes the
      file.
  - P2: with a live source reader, retain_plan(SRC/archive.sqlite-ſhm) fails with EEXIST only because the real -shm
    exists, and the existing -shm is unchanged. That is incidental, not the guard.
  - Effect: same class as the original F1. The owner's retained recipe is lost, and no evidence byte is altered.
    Recovery requires re-planning with the same nonce from an unchanged source.
  - Mitigation: "-journal" and "-wal" contain no letters with non-ASCII case-fold equivalents. Only "s" in "-shm" (and
    in "sqlite", which the inode check covers) is exposed. The spelling cannot be produced by accident.
  - Not tested: other filesystems or collations, and backup/recovery outputs that share sqlite_destination (an
    inherited pre-existing exposure, outside this diff).
  - Follow-up:
    - Make the check rely on filesystem identity, not name folding. For example: refuse a plan whose canonical parent
      directory is the source's or destination's directory (SQLite owns sibling names there), or after creation
      verify that no SQLite family name resolves to the plan's (dev, ino).
    - Pin it with a long-s regression on both families and correct the :426 comment.
    - Concurrent uncommitted parent-worktree edits appear to attempt this. They are unreviewed here and need their
      own review.
F-B [INFO] retain_plan routes the plan through sqlite_destination, which also refuses when "<plan>-journal/-wal/-shm"
    siblings exist, with the error "destination SQLite sidecar already exists". This is harmless over-refusal with
    destination-flavoured wording.
F-C [INFO, performance tension] Per-batch cost is linear in the copied prefix, not quadratic.
  - Each batch runs a full source and destination audit, then re-reads and compares every previously copied object
    and record on both sides (copied.rs:400-434).
  - A full copy with a fixed budget is therefore O(n^2/budget) in total I/O.
  - The design records full audits as an explicit cost with no performance claim. The disclosure would be more
    precise if it named the prefix re-comparison.
F-D [INFO] R9: the length half of the object-prefix compare (copied.rs:414) survives. The length mismatch is caught
    earlier by audit/full_audit, and the wrong-length test asserts only is_err. Redundant defence, not a gap.
