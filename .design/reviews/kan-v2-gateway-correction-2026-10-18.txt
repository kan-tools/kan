## Findings

1. **Medium, availability. The docs mislabel the remaining denial risk.**
   - Oldest-pending eviction (`src/evidence_gateway.rs:481-488`) means a remote collector is locked out by roughly 32 bare TCP connects per round trip (R6). That is about 640/s at 50 ms, and far fewer on slow links.
   - This needs no TLS bytes and almost no bandwidth, yet the design and `docs/V2-GATEWAY.md` describe it as "CPU/bandwidth flooding".
   - It is a large improvement over the previous 8 sockets per 15 s. The fix is not deployed, and failures are visible 502s, not lost evidence.
   - Follow-up: limit pending connections per peer, or protect connections whose handshake is in progress, and correct the docs before exposing the gateway beyond loopback.
2. **Low–medium, provenance. `request-outgoing` is not the full set of application headers sent** (R1). The docs exclude only "framing/host" fields, and `accept` is neither. The Python oracle checks only that `x-api-key` is named as an omission; it never compares outgoing header values with what the provider received, which is why this got through.
