API AUTHORITY
- Context is caller-supplied trust, never read from the envelope. Correct.
- verify() treats `previous` as authority. Probe: a predecessor derived from row 2's OWN body
  yields Verified for row 2 with row 1 never seen. Frontier has pub fields + Default, and
  Verified::frontier() returns the same type used as trusted input. The doc comment on Verified
  ("exact record/chain verification") overstates; the chain is only relative to the caller's input.
  The proof-aware spool release in the design needs a detached single-proof check, and today the
  only way to get one is to fabricate a predecessor. Add an explicit unchained API or type
  before that slice.
- issue() is a pure signer that refuses to return anything it cannot verify (pinned-issuer,
  admitted-issuer probes). It is not an admission authority; the store must keep it off raw paths.
- The codec accepts the same manifest at two heights, retained-verified before admitted, and an
  issuedAt regression (probe). Purpose ordering is documented as a store invariant. Duplicate
  manifest across heights is not named in the design as a store audit check.
