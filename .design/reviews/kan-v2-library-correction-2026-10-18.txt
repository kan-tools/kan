## Remaining findings
1. **AC-3 is still unmet.** One missing or corrupt object still fails its whole page, and absence is still reported as corruption (`evidence_service.rs:625-627,672-674`). This is now disclosed (`docs/V2-LIBRARY.md:91-96`), not fixed.
2. **The catalog is all-or-nothing.** One forged or unreachable scope makes the whole catalog return 503 (`evidence_library.rs:55`). Because this happens before the Library opens, the UI locks (`app.js:39`). Under df74506 a forged scope merely vanished; now every valid neighbour is hidden. That's honest and documented (`V2-LIBRARY.md:104-106`), but it cuts against the telos.
3. **The queue test can't tell queued from unbounded.** It has no elapsed-time lower bound, so it also passes with the execution limit removed. That's mutants Q01 and Q02, which finish about 4 s *faster* because the fifth request is served at once. The 12-socket bound and the 6 s and 35 s deadlines are also untested (Q03–Q06 survive). On the 100 ms settle: it isn't what makes the reverted code fail. The old code dropped the fifth socket in the accept loop regardless of timing, and my probe P1b got the same result with no settle at all. It's only a scheduling assumption, and when that assumption fails the test passes silently rather than failing.
4. **Minor gaps:**

   - Duplicate and badly shaped capability lists aren't tested (K13, K14).

   - A *signed* denial caused by clock skew still hides a scope without saying why. That's the intended single-denial-shape design, but "the catalog cannot silently go empty" only holds for signature failures.
5. **Still open from the first review:** the remote-call and connection timeout budgets aren't composed; the token comparison isn't constant-time; there's no external-request trace; and real-browser coverage of all states is partial.
