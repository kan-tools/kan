CONCURRENCY BOUNDARY (challenged; judged REASONABLE, not laundering)
The disclosure says concurrent append and same-height tip replacement are fenced; an arbitrary
privileged rewrite of an EARLIER row after audit, preserving tips, is not. Reasons this is sound:
(1) REQ-2 demands "the existing audited-frontier transaction fence"; legacy Service has exactly
the same audit-then-(through,tip) boundary, and this adds the tip statement CID. (2) Every
statement commits to previousAttestation (statement CID), so all authoritative history (manifests,
receipts, proofs, purposes, times) is hash-committed to the fenced tip statement. An earlier
rewrite cannot be made chain-consistent; it is detected by the next strict audit and by any
reader verifying from a pin. The only tip-preserving changes are payload deletion/corruption
(an availability event the design handles as degraded state) and derived columns (re-derived by
verify_contents). (3) The new proof is still truthful about what it signs. AC-2's "concurrent raw
append conflicts" is met (author test + P6). The disclosure was added during implementation but
narrows nothing the design required.

FINDINGS (none blocks this storage checkpoint)
F1 [medium, test gap] Four non-redundant checks lack committed regressions; the author suite passes
   10/10 with each deleted, my probes fail at named assertion lines:
   RM1 retry envelope equality (attested.rs:332)  -> killed only by P3 (probe line 171)
   RM2 retry receipt re-verification (337-343)    -> killed only by P4 (probe line 221)
   RM3 single historical issuer (199-201)         -> killed only by P5b (probe line 309)
   RM4 P-256 issuer roundtrip in validate (50-56) -> killed only by P7 (probe line 374)
   Commit P3/P4/P5a/P5b/P7 (or equivalents) before the next slice relies on these properties.
F2 [low] A stored-receipt swap during retry (P4) returns Failure::Invalid: proof errors map
   evidence::Error -> Error::Record -> Failure::Invalid. An integrity race should be Conflict or
   Corrupt, not caller-invalid input; matters once an RPC exposes the class.
F3 [medium, lifecycle; qualifies AC-3] Legacy openers "refuse" profile 2 but physically write it:
   with a crash-left WAL, Ledger::open and Ledger::resume_initialization open read-write, refuse,
   and on close checkpoint the WAL into archive.sqlite and delete it (P10: main_changed=true,
   wal_after=None). RecoveryReader leaves media untouched. Logical content survives (Archive::open
   verifies through=1 afterwards). Author test asserts only is_err. AC-3's "old binaries refuse the
   new profile before writes" must be qualified as "before logical writes", or current openers
   must probe the profile read-only first. Already-released binaries cannot be changed.
F4 [low-medium, lifecycle] Interrupted Archive::create (empty file after FileCreated) is
   unrecoverable through profile-2 APIs (create: EEXIST; open: unknown profile), but legacy
   Ledger::resume_initialization adopts it as profile 1 (P8: user_version=1). No evidence is lost
   (file was empty), but an owner who intended profile 2 silently gets profile 1. Design already
   lists profile-2 initialization recovery as remaining; it should refuse or explicitly choose.
F5 [low, surface/AC-5] The typed SQL helpers are inventoried, not enforced. NC1: a raw
   `tx.execute("UPDATE attestations ...")` added to attested.rs passes surface_conformance (19/19)
   and the store suite (10/10); there is no Clippy/SQL policy. NC5: an uncatalogued index on
   attestations passes everything (catalog binds columns only), while AC-5 says "every new stored
   field and index". Positive controls hold: NC2 (extra facade call) and NC3 (facade changed to
   INSERT OR REPLACE, which would permit proof overwrite) are caught by the inventory/digest only
   (store suite passes under NC3), and NC4 (uncatalogued table) is caught only by
   evidence_attested_store::database_columns_match_independent_surface_catalog (surface 19/19).
F6 [low, pre-existing] Hostile oversized WITHOUT ROWID object rows are fully materialized during
   integrity_check on writable open, despite the new length limit (see above). The future degraded
   read-only reader must not inherit this; the limit added to Archive is not what bounds the
   envelope case (integrity_check's CHECK evaluation refuses first). `let _ = set_limit(..)`
   silently ignores failure where RecoveryReader uses `?`.
F7 [low, test fidelity] Author mutation "signature" flips the envelope's final byte, which lies in
   the nested statement (DAG-CBOR orders "signature" before "statement"). P2 asserts the true
   signature-only flip refuses with "invalid attestation chain". Store mutation tests assert is_err
   only; most cases are also refused by legacy verify_contents, so attribution is weak.
F8 [doc] RFC 4 still says "The new SQLite profile and atomic proof insertion ... remain to be
   implemented and qualified together", contradicting this separately qualified checkpoint.
F9 [prerequisite, auth] Archive::admit takes one caller-chosen &Grant. Nothing in the type stops
   a future adapter building Grant{principal: request.principal, append: true}. Before the RPC
   slice, hold the configured grant table in Archive (as Service::new does) or make Grant
   constructible only from configuration.
F10 [prerequisite, schema/migration] Profile 2 is pinned to an exact sqlite_schema at
   user_version 2, but the design still requires authoritative surfaces this schema lacks: upgrade
   plan/historical-issuer pin (the audit enforces a CONSISTENT historical issuer, not one pinned to a
   plan), incomplete-recovery descriptor and resolution records. Profile 2 also has no backup,
   rebuild or recovery path (all refuse it). Do not let any profile-2 archive hold real evidence
   until those land, or plan an explicit profile bump.
F11 [tension, disclosed] Each admission runs integrity_check, a full object scan and full chain
   signature verification: O(archive) per append, O(n^2) cumulative. This is honest as a
   correctness baseline but stands in tension with telos/performance-at-scale. A cached verified
   prefix needs its own integrity review, as the design says.
Equivalent/redundant (not defects): RM6 lock-time proof cardinality (subsumed by the snapshot fence
   plus the attestations PK) and RM7 lock-time binding recheck (the signature always uses owner
   config; the next audit refuses DB drift) both survive all tests.
Codec follow-ups: F1 short-DID regression is CLOSED (catch_unwind + "issuer-encoding" for four
   short DIDs; the author's control reproduces the dependency panic). F2 is substantially closed
   (envelope-canonical, envelope-bound, row-after-genesis, pinned-frontier, chain-commitments
