2. North star
-----------------------------------------------------------------
telos/raw-data-and-projections (Decision bafyreied3rk…): "Raw attested data is retained in
full and never collapsed in the store. Every simplification … is a determined projection …
A field holding a computed value is the failure mode." The telos deliberately declares no
witnesses (Observation bafyreicakl3…). I invent none.
The work serves this telos:
  - availability is sampled and never stored;
  - retained-verified is present-time, never backdated;
  - source archives are preserved byte-exactly;
  - an unsigned historical receipt is never reinterpreted as a signature (design :252-253).
Tension: InTensionWith telos/performance-at-scale. The correction resolves this honestly:
bounded descending pages plus process-local MAC cursors, with no persistent pin cache.
The cost is that after a reader restart, reaching a deep row means paging down from the
tip again (design :279-280). That cost is declared, and accepting it is correct.
One telos risk (F-new-5): the recovery descriptor is called "authoritative" but records
an observation, and clearing it is unspecified.

5. Findings
-----------------------------------------------------------------
R1 (must decide before the reader source path / proof-aware spool release; no byte change)
   Historical issuer H != current issuer C contradicts the request audience rule.

   The design allows H != C for retained-verified (:249-251), says exact retries of copied
   operations return retained-verified (:299-301), and says source reads verify the signed
   writer request (:288-290). But:
     - RFC :303-309: requests bind the destination service did:key as `audience`; admission
       compares it with the serving identity "before accessing storage"; "key rotation and
       audience transition are not implemented by this profile."
     - Service::execute refuses audience != self.issuer() BEFORE the duplicate lookup
       (src/evidence_service.rs:549-551). A spooled legacy op addressed to H is
       AccessLimited by C, so the spool never drains.
     - The reader source read refuses signed.request.audience != access.issuer
       (src/evidence_reader.rs:285-289), so every retained-verified row with H != C fails as
       Corrupt. check_pin (:182) and decode_record (:32, receipt.issuer == access.issuer)
       pin the same single identity.
     - verify_retained_request already binds receipt.issuer == request.audience (:338-341),
       so a consistent rule exists. It just isn't stated for the proof profile.
   Choose one and write it into design and RFC:
     (a) The first profile requires H == C: the upgrade plan refuses H != C. This matches
         RFC :308-309, but then the design's "historical issuer can differ" text must go.
     (b) Specify that for retained-verified rows the reader and the service dedupe path
         accept audience == receipt.issuer, bound through the C-signed proof's receipt CID.
         Exact retries then match the stored operation before the audience gate. Never
         relax the audience check for admitted rows.
   Recommended: (a) for the first profile. Leaving it implicit invites an implementer to
   relax the audience check globally, which reopens request redirection.
   Probe: P11.

F-new-1 Snapshot/page/cursor vectors.
   Add Python oracle functions and fixture vectors for:
     - the anchor (snapshot tip CID equality);
     - descending predecessor equality;
     - genesis termination, past-genesis, an empty page before genesis, inconsistent
       complete flag;
     - same-height alternate statements at the tip (purpose/time/receipt);
     - a fork splice.
   This is design :326, which is currently unmet. Cursor/MAC framing may follow, as RFC
   :173-174 already declares. My descend() in probe_correction.py is a working sketch.

F-new-2 Fixture completeness. Add labelled negatives for section 4 items a-i, and pin
   schema-level receipt negatives for Rust:
     - P7: durability 'best-effort' and an extra receipt field are ACCEPTED by the Python
       oracle; a missing issuer raises KeyError, not a label;
     - P6: a junk historical issuer Author is accepted for retained-verified.
   The Python oracle declares receipt schema "Rust-only" (RFC :246), so these must be Rust
   vectors.

F-new-3 Purpose ordering and historical-issuer consistency are not verifiable (P5).
   - The design says upgrade copies a complete legacy prefix with one pinned legacy issuer
     (:255, :312). The oracle accepts admitted -> retained-verified -> admitted ->
     retained-verified with three receipt issuers and decreasing issuedAt.
   - The committed positive vector is itself admitted(1) -> retained-verified(2), an order
     the specified upgrade can never produce.
   - Specify the reader rule:
       * retained-verified only in a contiguous prefix from sequence 1, all with one receipt
         issuer;
       * admitted only after that prefix;
       * issuedAt non-decreasing, or state explicitly that it is unchecked.
   - Reorder the positive vector to retained-verified -> admitted.
   - Also state that service admission never mints retained-verified, except by returning
     the stored proof on exact retry.
   This is not a trust escalation (C is trusted anyway). It is a cheap invariant that would
   otherwise exist only operationally.

F-new-4 Assertion provenance in the UI. The design separates issuer attestation from
   writer verification (:72-76, AC-6). It does not say:
     - "missing" and "corrupt" are signed SERVICE assertions the reader cannot verify;
     - only "available" is ever reader-verified, and only on a source read (hash + writer
       signature);
     - snapshot through/tip/genesis is a service assertion with no freshness guarantee.
   Classification to pin in the requirements:
     caller assertion  = unsigned frontier/after/through coordinates and cursor bytes
                         before MAC check (never trusted: :277-279);
     service assertion = signed reply (snapshot, availability state, page) and the C-signed
                         statement (admitted / retained-verified);
     writer verification = reader-side verification of the retained signed request
                         (payload present only);
     receipt.issuer    = an unsigned field, bound only via the C-signed receipt CID.

F-new-5 Recovery descriptor (design :314-319).
   - It is called "authoritative" but holds an observation made at a point in time. Specify
     that it is an observation record (observer, time, source pin), not a current state.
   - Specify how "explicit owner recovery" lifts the strict-open refusal WITHOUT deleting
     or overwriting the descriptor (for example a new copy, or an appended resolution
     record). Otherwise the record of loss gets destroyed, against the telos.
   - Its surface row is still to come.

F-new-6 archiveId provisioning.
   - Readers and spool clients check a "configured" archiveId (:298, :325). Say where that
     comes from: the plan output delivered out of band. TOFU from the first snapshot would
     weaken the "foreign archive" check.
   - An owner-copy changes archiveId, so every reader/client config must be updated.
   - Resume binding (:172) omits archiveId even though the plan (:115) includes it.

F-new-7 Source quiescence.
   - Resume refuses differing plan inputs, so there is no catch-up to a later legacy tip.
   - State that the legacy service must stop admitting between plan pin and cutover, or
     appends acknowledged with legacy receipts are absent from the destination. Production
     cutover is out of scope, but this constraint belongs in the plan semantics.

9. Verdict rationale
-----------------------------------------------------------------
**APPROVE WITH FOLLOW-UPS** (design/protocol readiness only; no runtime approval).

All three original blockers are resolved at the protocol level, and none of my findings
requires changing the statement bytes:
  - B1: every named check now has a re-signed, labelled vector. I reproduced 27/27 kills.
  - B2: one host-resident current issuer signs everything; admitted-issuer and receipt
    binding are vectored.
  - B3: archiveId is in the bytes; descending anchored pages and process-local MAC cursors
    are specified concretely enough that an independent sketch rejects forks, tip
    substitutions and past-genesis pages; the non-guarantees are stated honestly.

What remains:
  - R1, one real contradiction: allowing historical issuer != current issuer conflicts with
    the RFC's request-audience rule, and the existing service and reader code would refuse
    spool retries and source reads. Resolve it in text, preferably by requiring H == C for
    the first profile, before implementing those two paths.
  - The fixture set needs snapshot/page vectors, conjunct-level negatives and a
    purpose-order rule (F-new-1..3).
  - F-new-4..7 are specification clarifications.
These are concrete and bounded, and none undermines telos/raw-data-and-projections.
The build still needs Rust parity, the runtime ACs and its own fresh Opus review.
