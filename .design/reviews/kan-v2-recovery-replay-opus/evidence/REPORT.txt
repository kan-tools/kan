FINDINGS — SCOPE A (pure replay)

A-F1 [MEDIUM-LOW — consumer contract / design coherence. Decide before any physical restorer or UI
consumes Restoration.]
- Replay accepts a restored candidate for an issuer-referenced service request whose bytes match the
  CID and authenticated length but fail writer verification. It returns that candidate as a Restoration
  with basis IssuerMetadata (probe P01). The failure surfaces only if a later intent is signed
  ("output member validation").
- The identical bytes present as the ORIGINAL object make the whole member refuse (probe P02). The
  member rule is explicit: "A hash-valid request that fails its writer signature or exact manifest
  binding is invalid member evidence, not a repairable missing-byte condition" (codec:427-429).
- So the replay projection reports a repair candidate for a condition the member defines as
  unrepairable. That candidate can never publish (P01's sibling vector
  restored-content-address-does-not-certify-writer), but nothing in Replay/Restoration says so.
- This is NOT incorrect acceptance under the current replay text, which defers writer re-audit to the
  intent (codec:494-496). It is a coherence gap.
- Required (choose one and record it):
  (a) verify restored service-request candidates against their manifest binding and writer signature
      at restoration, refusing the history as the member would; or
  (b) expose a per-Restoration writer-verification status, and require the future restorer never to
      sign such a restoration and the UI never to present it as recovered evidence.

A-F2 [LOW-MEDIUM — test gap; close before the replay checkpoint is accepted.]
- Five semantic guards are correct in code, but the author suite does not pin them. Removing any of them
  either passes the whole author suite or only changes a refusal label. Only reviewer probes show the
  resulting hostile acceptance:
  - RM05 candidate hash (src:532);
  - RM06 candidate authenticated length (src:528-531). This is the positive half of C-F1;
  - RM07 output losses empty (src:435-438). A corrupt orphan with a self-consistent O1 publishes;
  - RM11 checkpoint context (src:494). Foreign observer/issuer/profile/scope/archive pins are accepted;
    the author assertion at tests:235-239 conflates the context fault with the truncation fault from
    tests:230;
  - RM18 partial-copy referenced length override (src:335).
- Required:
  - Add P03, P04, P05 and P20 (or equivalents) to the independent Python constructor/fixture as
    single-fault hostile vectors.
  - Make the foreign-checkpoint assertion single-fault: run it on the untruncated history and cover the
    observer, issuer and profile fields.
  - Demonstrate RM05/RM06/RM07/RM11/RM18 as compiled semantic controls.
  - Until then, C-F1's replay-side length constraint is qualified only by this review's probes.

A-F3 [LOW / INFO — spec–oracle equivalence by arithmetic only.]
- The greedy "largest prefix whose envelope fits 16 KiB" loop (src:358-381) is unreachable: the maximal
  32-entry envelope is 3770 B (probe arithmetic).
- The Python oracle uses fixed 32-entry chunks (recovery_replay_vectors.py:103), so the two agree only
  because of that arithmetic, and neither independently exercises the envelope rule.
- Pin the bound as a test, so a future schema change that enlarges entries cannot silently diverge, or
  simplify the spec to "32 per event" with the bound as an asserted invariant.

A-F4 [INFO — oracle independence, stated precisely.]
- The Python replay() state machine is a close transliteration of the Rust one: same labels, same order.
- Its independent value is in signed construction, the R1/O1/union computations and the selected-output
  writer-signature check (check_writer). It is not an independent derivation of the state rules.
- It is not a member validator, as declared (P02 accepted by the oracle).
- The reviewer probes supply design-derived expectations beyond its corpus. All 20 matched Rust.

A-F5 [INFO — resource accounting notes.]
- expected_partition re-encodes up to 32 candidate statements per unavailable event. This work is not
  charged to scan bytes; it is bounded (≤32 × ~3.8 KiB per event) and its polling is per observation.
- Observer and writer signature verification are individually bounded, not interruptible.
- The scan metric counts documented input passes: member 2×, observations 1×, candidates 1×, R1 2×,
  virtual audit 2× + O1 1× per distinct selection. It is monotone; minimum-1 refuses (probe).
- It is not RSS or CPU, as documented.

A-F6 [INFO — prerequisite for the job layer.]
- Checkpoint has public fields, and nothing in the type prevents a caller from re-feeding replay.latest()
  as the "external" pin, which would remove rollback protection.
- The provenance rule ("do not derive the external pin from the bundle", codec:288-289) must be enforced
  by the owner job's storage boundary, not assumed from this API.

No production correctness defect, invariant violation or incorrect acceptance was found in the frozen
replay code. Every hostile probe outside the author corpus refused, and every positive probe matched
