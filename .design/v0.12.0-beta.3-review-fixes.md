# v0.12.0-beta.3 — review fixes

## Summary

Bugfix milestone answering the six-dimension cold review recorded as
`review/full-pass-v0.12` (claim `bafyreibqp…vf2y`, artifact report
2026-08-10). Scope: every finding that is fixable without a design fork —
the store race (F1), the mislabeled repair loss (F2), the pre-auth
`.claims/` panics (F3), MCP enum drift (F5), trust-weight surface honesty
(F6), silent wrong-writes (F8), fold ordering/retraction-chain/read-surface
splits (F9), git argument hardening, and the documentation drift (F7).
Explicitly deferred to design work, not patched here: F4 (Debug as wire
contract — needs a schema-evolution compatibility plan for already-published
files), real trust-weight semantics (implement-or-remove fork), F2's
resync-at-block-boundary recovery, and all strategic findings (F10–F12).
Each fix ships with a test that fails without it, in the same commit
(CLAUDE.md rule; verified by reverting the fix hunk).

## Requirements

- REQ-1 **Recovering writers must not strand concurrent appends.** A `Log`
  opened with `head_stale` must, under the write lock, re-read `HEAD` and
  the CAR and adopt the on-disk root when it is walkable, using its
  recovered root only when the log is still broken at that moment. No
  first-append interleaving on a fresh workspace may leave a committed
  claim unreachable.
- REQ-2 **Repair never destroys silently.** Before `rewrite_car` replaces
  the CAR, the pre-repair file is copied aside (`repo.car.damaged-<micros>`)
  and the operator is told where it is. The tolerant-read warning and the
  HEAD-recovery warning must not claim "no claim was lost" when the
  damaged-tail read may have dropped later blocks. A zero-byte or
  header-unreadable CAR gets a named error stating the file, the state, and
  that kan will not modify it — not a raw varint decode error.
- REQ-3 **No byte sequence in `.claims/` may abort the process.**
  `split_records` uses checked arithmetic and char-boundary-safe slicing;
  a record whose declared `text_len` is absurd or lands inside a UTF-8
  character is treated as a malformed record (separator fallback / skip),
  and `hex_decode` rejects non-ASCII input, so ingest keeps its stated
  warn-and-skip contract.
- REQ-4 **MCP speaks the vocabulary its descriptions teach.** Enum
  parameters (`relate` kind, `status`, subject `kind`) accept kebab-case,
  with the previously-advertised PascalCase kept as serde aliases;
  caller-shaped `actions::Error`s surface as `invalid_params`, not
  `internal_error`; the `trust` parameter doc names the real accepted forms
  (`me`, `local`, `roles`, `role:<name>`, DIDs) instead of internal fold
  names. Wire serde on `claim.rs` types is untouched — signed content
  encoding must not change.
- REQ-5 **The trust surface tells the truth about weights.** A `--trust`
  selector carrying an explicit weight warns that weight magnitudes are not
  yet folded (membership only), and `kan show --help` and the README stop
  implying down-weighting works.
- REQ-6 **No silent wrong-writes.** A recording verb given a single
  positional that exactly names an existing subject is refused with
  guidance (escape hatch: explicit `--subject`). `publish` refuses a
  subject with zero live claims instead of minting a Publication for a
  typo.
- REQ-7 **Fold ordering is a property, not an accident.** The fold and its
  callers order by `(rev, cid)` (index `ORDER BY` included), so same-`rev`
  claims fold identically regardless of input order; `excluded_by_retraction`
  handles retraction chains by derivation (latest-first single pass:
  effective iff not itself effectively retracted), so retracting a
  retraction-of-a-retraction reinstates the middle retraction; `show`'s
  superseded-marking classifies under the same computed-edge set `status`
  uses (SPEC §9 step 2b).
- REQ-8 **Claim-derived git arguments are inert.** `Sha` values are
  validated as hex at the boundary (`git::is_hex_sha`) before reaching `git
  merge-base`, so a crafted `-`-prefixed anchor is rejected as a non-edge
  and can never be read as an option. (Hex validation alone closes the
  surface; an earlier draft of this doc also promised a `--` separator,
  which was not implemented and is not needed — a validated hex string
  cannot start with `-`.)
- REQ-9 **The documents describing the system describe this system.**
  SPEC §2 (roles/`RoleDeclaration`/`TrustBase::Local` replace the
  `AgentKey` story as shipped mechanism, with `AgentKey` marked legacy),
  §4.2/§7 (kind and relation inventories match `claim.rs`), §4.5.1
  renumbered out of §5, §11's trust-policy fence amended to record ADR-83;
  README gains a quickstart and the v0.12 identity-at-rest model;
  CLAUDE.md's relate list and stale "no in-tension-with" note corrected;
  SETUP-TODO's ghost `session` verb removed; `fold/trust.rs` module header
  count corrected.
- REQ-10 **Error text stops leaking internals.** Bad-CID errors drop the
  `error-atproto-dasl-decode-7` token; `observe --help` stops citing
  `subject_and_text`; top-level `relate` help lists all eight kinds;
  not-a-git-repo suggests `git init`.

## Architecture

No new modules. `src/store/log.rs` gains the under-lock stale-HEAD
re-read inside `reload_if_stale` (the lock is already held by
`append_locked`; the change is that `head_stale` triggers a fresh
disk read instead of an early return) and the damaged-copy step at the top
of `rewrite_car`. `src/transport/git_tree.rs` changes are local to
`split_records`/`hex_decode`. MCP enum mirrors live in `src/mcp.rs`
alongside the existing `RelateKindParam` (mirror-enum pattern; `claim.rs`
serde is deliberately untouched). The observe-guard needs the workspace's
live subject list, so it runs in the CLI handlers after
`cli::subject_and_text` resolves (a pure-parse layer cannot know what
subjects exist); MCP is unaffected (its `text` is a named parameter).
`excluded_by_retraction` is rewritten as the reverse-order derivation.
`(rev, cid)` ordering lands in `fold::fold`, `excluded_by_retraction`'s
sort, and `Index` `ORDER BY`.

## Resolved Questions

- Weighted trust: **warn, don't remove** in beta.3. The
  implement-or-remove fork is a design decision recorded for the
  structural post; removing syntax in a bugfix release would break
  README-taught invocations with no ADR behind the choice.
- Debug-as-wire (F4): **out of scope.** Changing published `.claims/`
  header rendering invalidates existing published trees; that is a
  schema-evolution design (ADR-44 contract) with a compatibility window,
  not a patch.
- `observe` single-positional semantics: **guard, don't repurpose.** The
  text-only convenience stays; only the case where the text exactly names
  an existing subject is refused, because that is precisely the case where
  intent is ambiguous and one reading writes to the wrong subject.
